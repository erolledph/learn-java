## 2026-04-07 - Cache curriculum navigation indices
**Learning:** The application's global `state` in `app.js` tracked navigation context via `currentLesson` and `currentModule` but lacked their respective indices (`currentLessonIndex`, `currentModuleIndex`). This led to inefficient O(N) nested array lookups (e.g., `findIndex`) in `previousLesson`, `nextLesson`, and `updateNavigationButtons` across the entire `JAVA_CURRICULUM` on every navigation event.
**Action:** When tracking global state for nested list items, always cache their indices alongside the objects to enable O(1) state lookups and avoid redundant traversals.

## 2024-04-13 - Stop Manual DOM Manipulation for CodeMirror Themes
**Learning:** The `app.js` contained a function (`applySyntaxColors`) that was manually searching and styling `.cm-*` classes in the DOM on every keystroke (`editor.on('change')`) with a `setTimeout`. This is a massive anti-pattern for CodeMirror, causing severe layout thrashing and performance drops. CodeMirror inherently handles syntax highlighting through parsing and appending classes, and styling is meant to be done purely via CSS (which is properly configured in `styles.css` for light/dark themes). Modifying DOM styles directly in JS overrides these theme classes and defeats CodeMirror's internal optimizations.
**Action:** Always verify if a library (like CodeMirror) natively supports a feature (like syntax styling/theming) via CSS before resorting to manual DOM manipulation on frequent events like keystrokes. Remove redundant JS-based styling that conflicts with CSS themes.
